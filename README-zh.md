# BPE-ZH: 中文 Byte-Pair Encoding 演算法實作

這是一個使用 Rust 編寫的命令列專案，用於演示 **Byte-Pair Encoding (BPE)** 演算法在中文文本上的標記化過程。

BPE 是一種數據壓縮技術，透過迭代地將最頻繁出現的相鄰位元組對（或字元對）合併為一個新的單元，來建立一個詞彙表。它在自然語言處理（NLP）中被廣泛應用於文本標記化（Tokenization）。

## 專案結構

```
.
├── Cargo.toml      # Rust 專案設定檔
├── README.md       # 本說明文件
└── src
    └── main.rs     # 主要程式碼
```

## 程式碼解析 (`src/main.rs`)

程式碼主要包含以下幾個部分：

1.  **`Token` 結構**：用來表示一個標記（token），並記錄它是否為空格。
2.  **`split_chars`**：將輸入的文本初始化，分解成單一字元的 `Token` 序列。
3.  **`count_bigrams`**：統計 `Token` 序列中所有相鄰（非空格）標記對的出現頻率。
4.  **`most_frequent_bigram`**：從頻率統計中找出最常出現的標記對。
5.  **`merge_tokens`**：將指定的標記對合併成一個新的 `Token`。
6.  **`run_bpe`**：BPE 演算法的主要迴圈。它會重複執行「計頻」和「合併」的過程，直到達到指定的迭代次數或沒有可合併的標記為止。
7.  **`main` 函式**：程式的進入點。它包含一個固定的中文繞口令作為示範文本，並呼叫 `run_bpe` 來執行演算法。
8.  **`tests` 模組**：包含單元測試，確保各個函式的正確性。

## 如何使用

這個工具現在使用子命令（subcommand）來區分不同的運作模式。基本語法如下：

```
./bpe-zh [輸入選項] <命令> [命令選項]
```

#### 1. 建置專案

首先，使用 Cargo 建置專案以獲得最佳效能：
```bash
cargo build --release
```
可執行檔會位於 `./target/release/bpe-zh`。

#### 2. 輸入選項 (全域)

您必須選擇以下其中一種方式來提供輸入文本：

| 短參數 | 長參數 | 值           | 說明                     |
| :----- | :----- | :----------- | :----------------------- |
| `-f`   | `--file` | `<FILE_PATH>`| 從指定的檔案路徑讀取文本。 |
| `-t`   | `--text` | `<TEXT>`     | 直接從命令列提供文本。   |


#### 3. 命令 (Commands)

您必須選擇以下其中一種命令來執行：

##### `percentage`

當 Token 總數達到原始數量的某個百分比時，演算法停止。這是控制壓縮率最直觀的方式。

**選項:**
| 短參數 | 長參數       | 值       | 說明                                           |
| :----- | :----------- | :------- | :--------------------------------------------- |
| `-p`   | `--percentage` | `<1-100>`| **目標壓縮率**。預設值為 `70`。                |


##### `frequency`

當找不到任何出現次數超過 `n` 的字元對時，演算法停止。這適合用於建立一個只包含高頻組合的詞彙表。

**選項:**
| 短參數 | 長參數      | 值      | 說明                                     |
| :----- | :---------- | :------ | :--------------------------------------- |
| `-n`   | `--frequency` | `<>=2>` | **頻率閾值**。當最高頻率 ≤ n 時停止。 |


## 範例

#### 範例 1: 使用 `percentage` 模式壓縮到 50%

```bash
./target/release/bpe-zh --text "劉奶奶找牛奶奶買牛奶，牛奶奶給劉奶奶拿牛奶" percentage -p 50
```

#### 範例 2: 使用 `frequency` 模式，直到最高頻率小於等於 2

```bash
./target/release/bpe-zh -t "a a a a b b b c c d" frequency -n 2
```
*在這個例子中，`a a` 會先被合併，然後是 `b b`。因為 `c c` 的頻率只有 2，演算法會在處理完 `b b` 之後停止。*

#### 範例 3: 從檔案輸入並執行 `percentage` 模式

```bash
# 建立檔案
echo "柳奶奶的牛奶會流奶" > input.txt

# 執行程式
./target/release/bpe-zh -f input.txt percentage -p 60
```

#### 範例 4: 查看特定子命令的幫助

```bash
./target/release/bpe-zh percentage --help
```

## 開發歷程與分析

本專案的功能演進與開發過程反映了命令列工具設計的幾個常見階段與挑戰。

### 功能演進

1.  **初始版本**: 程式邏輯與輸入文本寫死在 `main` 函式中，僅用於功能演示。
2.  **參數化 V1**: 引入 `clap`，增加了 `--file`、`--text` 和 `--max-iterations` 參數，將工具通用化。
3.  **參數化 V2**: 根據需求，將停止條件從固定的「迭代次數」改為更直觀的「Token 壓縮百分比」 (`--percentage`)。
4.  **最終架構 (子命令)**: 為了同時支援「百分比」和新增的「頻率」兩種截然不同的運作模式，進行了最大的一次重構。引入了 `clap` 的子命令（subcommand）架構，將程式分為 `percentage` 和 `frequency` 兩個清晰的模式。這是處理多個獨立功能模組的最佳實踐。

### 開發與除錯分析

在最後的子命令重構階段，遇到了幾個值得記錄的技術挑戰：

*   **`clap` 參數驗證**: 在為 `frequency` 模式的 `-n` 參數設定 `value_parser` 時，對 `clap` v4 的 `range` 驗證器語法有誤，導致了多次編譯失敗。最終的解決方案是，放棄在參數宣告中進行驗證，改為在 `main` 函式中解析參數後，用一個簡單的 `if` 條件進行手動檢查。這個方法雖然不夠「優雅」，但更直接、更穩定，且能繞過特定版本的 `clap` 語法問題。

*   **`println!` 格式化字串錯誤**: 在一次修復中，意外地在 `println!` 的格式化字串中引入了無法識別的非 ASCII 字元，導致了 `invalid format string` 編譯錯誤。這個低級錯誤提醒我們，在複製貼上或快速編輯程式碼時，必須格外小心，特別是在處理字串時。

最終，透過這些迭代和修正，程式碼達到了一個穩定、結構清晰且功能強大的狀態。
